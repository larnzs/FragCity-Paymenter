# Deployment

Deploy only FragCity-owned add-ons into an existing, separately installed Paymenter v1.5.9 instance.

## 1. Extension ZIP installation

Use the native Paymenter uploader and the generated packages described in [Plug-and-play extension installation](../docs/INSTALL-EXTENSIONS.md).

The repository's GitHub Actions workflow builds one ZIP per extension from main:

- FragCityAPI — Admin → Extensions → Others
- FragCitySupportAPI — Admin → Extensions → Others
- FragCityCS2 — Admin → Extensions → Servers

Upload one ZIP at a time. Install in this order: FragCityAPI, FragCitySupportAPI, then FragCityCS2. Do not upload the outer GitHub Actions artifact ZIP; extract it first and upload the individual ZIPs.

Do not manually create extension database rows or copy extension files over an existing installation as a normal workflow. For updates, use the Paymenter uploader so the extension upgrade lifecycle hook can run.

## 2. FragCity theme deployment

The FragCity theme is not a Paymenter Extension and is not included in the drag-and-drop ZIP packages. It uses a separate Vite build directory.

Build the theme only when intentionally deploying the Paymenter theme:

    cd /var/www/paymenter

    # Install build dependencies only when node_modules is missing.
    test -d node_modules || npm install

    # Build the FragCity theme into public/fragcity/.
    npm run build fragcity

    # Do not activate the theme unless this manifest exists.
    test -s public/fragcity/manifest.json

After changing theme Blade views, clear compiled views and Laravel caches:

    php artisan view:clear
    php artisan optimize:clear

The public/fragcity/manifest.json file is generated by Vite and is not committed to this add-ons repository.

## 3. Sensitive GSLT Checkout patch

Paymenter v1.5.9 stores its native Checkout `configOptions` array in a URL-synchronized property. A Steam GSLT must not be placed in that array because it can appear in browser history, copied links and Referer headers.

Before enabling the `STEAM_ACC` text Config Option on the CS2 Product, apply this version-specific patch:

`deployment/patches/paymenter-1.5.9-sensitive-config-options.patch`

The patch file already contains every required change to `app/Livewire/Products/Checkout.php`: a separate non-URL Livewire property, migration from the URL-bound array, optional 32-character validation, matching validation attributes, and forwarding the value to Paymenter's normal Cart/ServiceProperty flow. Do not copy only selected hunks or put the GSLT into a URL.

A complete, ready-to-review reference copy of that patched Paymenter core file is also committed at:

`app/Livewire/Products/Checkout.php`

This file is based on the official Paymenter `v1.5.9` source and includes the same GSLT changes as the patch above. On the shared host, back up the existing file and replace the host's `app/Livewire/Products/Checkout.php` with this exact file. This repository copy is a deployment reference only: do not upload it through Paymenter's Extension uploader, and do not treat it as a FragCity extension package. It is version-specific to Paymenter v1.5.9.

If you have shell access, run these commands from the Paymenter application root (adjust the patch path to the actual repository location):

```bash
git apply --check /path/to/FragCity-Paymenter/deployment/patches/paymenter-1.5.9-sensitive-config-options.patch
git apply /path/to/FragCity-Paymenter/deployment/patches/paymenter-1.5.9-sensitive-config-options.patch
git diff --check
```

On shared hosting without SSH, the patch cannot be executed by File Manager. Back up `app/Livewire/Products/Checkout.php`, then use the complete patch file above as the source of truth and apply all five hunks to that file. The patch target is only this one Paymenter core file; do not upload the patch file over `Checkout.php` and do not replace the whole core file with a different version. After editing, verify that every added hunk is present and that the original non-GSLT config-option handling remains unchanged.

The FragCity theme binds the GSLT input to `sensitiveConfigOptions`. Until the core patch is applied, keep the `STEAM_ACC` Config Option disabled; otherwise the stock URL synchronization can expose the token. Keep a backup of the original file because Paymenter core updates may require reapplying the patch.

After applying the patch, clear Laravel caches if the host provides that capability. No Vite rebuild is required for this PHP-only core patch.

## 4. Access boundary

FragCity customers use the Raw PHP FragCity website. Do not direct customers to the Paymenter customer portal or the Pterodactyl panel.

The Paymenter Admin area and Pterodactyl management interfaces remain restricted to authorized operators. All customer actions must be mediated by FragCity's backend.

## 5. Never overwrite

Deployment must not overwrite or replace:

- Paymenter core application files except the explicitly documented, version-specific Checkout patch above
- Official upstream language files
- .env or runtime secrets
- vendor
- database contents
- storage uploads, sessions, logs or cache

Deploy only the exact FragCity-owned theme/extension paths required for the current stage.
